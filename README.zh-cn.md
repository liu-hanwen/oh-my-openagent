# Oh My OpenCode（量化研究版）

量化研究的 AI 协作团队 (Quantitative Research AI Agent Harness)。

不是一个助手——是完整的研究体系。因子挖掘 (Factor Mining)、CTA 策略开发、Alpha 研究、回测验证——各司其职，并行运转，永不停歇。Claude 做策略编排，GPT 做深度推理，Kimi 跑系统化研究，Gemini 分析另类数据。

**奥卡姆剃刀 (Occam's Razor) 是我们的核心原则**：从最简单的因子开始，用证据驱动复杂度，而不是用参数数量堆出过拟合。

脏活累活我们替你干了。我们测试了一切，只留下真正有用的。

安装 OmO。敲下 `ultrawork`。开始你的量化研究。

### 自律军团 (Discipline Agents)

<table><tr>
<td align="center"><img src=".github/assets/sisyphus.png" height="300" /></td>
<td align="center"><img src=".github/assets/hephaestus.png" height="300" /></td>
</tr></table>

**Sisyphus** (`claude-opus-4-6` / **`kimi-k2.5`** / **`glm-5`**) 是你的主编排智能体。负责解析量化研究意图、制定研究路径、将任务分配给专家团队，并以极其激进的并行策略推动任务直至完成。他专注于两条研究主线：**因子挖掘 (Factor Mining)** 和 **CTA 交易系统研究**。

**Hephaestus** (`gpt-5.3-codex`) 是你的自主深度研究者。给他目标，不要给具体做法。他会探索数据结构、研究因子构建模式，端到端独立完成任务，绝不中途要你当保姆。*名副其实的正牌工匠。*

**Prometheus** (`claude-opus-4-6` / **`kimi-k2.5`** / **`glm-5`**) 是你的量化策略规划师。访谈模式下，他会深挖研究需求、识别数据假设的模糊地带，并在动一行代码之前产出经过严密论证的研究计划。

**Oracle** 是量化策略顾问。在完成重要回测或因子分析后、遇到复杂策略架构决策时、2 次以上因子验证失败时，召唤 Oracle 进行深度咨询。

**Metis** 是量化研究规划顾问。在规划前识别数据假设的隐藏风险、方法论的模糊地带、过拟合的潜在信号，并应用奥卡姆剃刀原则质疑不必要的复杂度。

**Momus** 是量化研究方案审查员。以毫不留情的批判眼光审查回测方案，检查统计有效性、过拟合风险、数据质量假设和方法论完备性。

**Librarian** 专注于文献研究。学术论文、金融数据源、量化方法论参考、行业基准——这是 Librarian 的主战场。

**Explore** 专注于因子探索。在你的因子库、数据管道、策略实现和研究基础设施中快速检索，找到相关的因子实现和模式。

每一个 Agent 都针对其底层模型的特点进行了专门调优。你无需手动来回切换模型。

> **注意**：Hephaestus 需要 OpenAI（或 GitHub Copilot / Venice）才能激活。如果你没有配置这些 provider，Hephaestus 将不会出现在 Agent 列表中。这是预期行为。

### 智能体调度机制（类别系统）

当 Sisyphus 把任务分配给子智能体时，他选择的不是具体的模型，而是 **类别 (Category)**。系统会自动将类别映射到最合适的模型：

| 类别                 | 作用领域                                   | 默认模型                  |
| :------------------- | :----------------------------------------- | :------------------------ |
| `visual-engineering` | 因子挖掘、构建与验证——系统化 Alpha 发现    | `gemini-3.1-pro`          |
| `deep`               | CTA 策略开发——趋势跟踪、均值回归、系统化交易研究 | `gpt-5.3-codex`           |
| `ultrabrain`         | 复杂策略架构、投资组合构建、风险模型设计   | `gpt-5.4` (xhigh)         |
| `artistry`           | 创意性风险分析、另类数据研究、非常规策略方法 | `gemini-3.1-pro`          |
| `quick`              | 数据处理、简单指标计算、快速因子运算       | `gpt-5.4-mini`            |
| `unspecified-low`    | 快速回测与验证任务                         | `claude-sonnet-4-6`       |
| `unspecified-high`   | 全面回测、前向优化、多资产验证             | `claude-opus-4-6` (max)   |
| `writing`            | 研究报告、策略备忘录、因子文档             | `kimi-for-coding/k2p5`    |

智能体只需要说明要做什么类型的研究，框架会自动选择最合适的模型来执行。你完全不需要操心。

> **关于 `deep` 和 `artistry` 类别**：这两个类别有 `requiresModel` 限制——`deep` 需要 `gpt-5.3-codex` 可用，`artistry` 需要 `gemini-3.1-pro` 可用。如果相应的 provider 未连接，这些类别的子任务不会被调度。

### 赋予 Agent 世界级的工具链

LSP、AST-Grep、Tmux、MCP 并不是用胶水勉强糊在一起的，而是真正深度的集成。

- **LSP**: 支持 `lsp_rename`、`lsp_goto_definition`、`lsp_find_references` 和 `lsp_diagnostics`。
- **AST-Grep**: 支持 25 种编程语言，能够理解语法树的模式匹配和代码重写。
- **Tmux**: 真实的交互式终端环境，支持 REPL、调试器以及 TUI 工具。Agent 的进程持久运行。
- **MCP**: 内置 Web 搜索、官方文档直连以及 GitHub 级代码搜索。

### 技能专属的按需 MCP 服务器

一堆全局 MCP 服务器极其消耗 Context 额度，我们修好了这个问题。

现在每个技能 (Skill) 都带着自己的专属 MCP。只在执行该任务时启动，任务完成即刻销毁。Context 窗口始终清爽。

### 拒绝瞎改：基于内容哈希的编辑工具

Harness 问题是真的。绝大多数所谓的 Agent 故障，其实并不是大模型变笨了，而是他们用的文件编辑工具太烂了。

受 [oh-my-pi](https://github.com/can1357/oh-my-pi) 的启发，我们实现了 **Hashline** 技术。Agent 读到的每一行代码，末尾都会打上一个强绑定的内容哈希值：

```
11#VK| function hello() {
22#XJ|   return "world";
33#MB| }
```

Agent 发起修改时，必须通过这些标签引用目标行。如果在此期间文件发生过变化，哈希验证就会失败，从而在代码被污染前直接驳回。

### 深度上下文初始化：`/init-deep`

执行一次 `/init-deep`。它会为你生成一个树状的 `AGENTS.md` 文件系统：

```
project/
├── AGENTS.md              ← 全局级架构与约定
├── src/
│   ├── AGENTS.md          ← src 级规范
│   └── factors/
│       └── AGENTS.md      ← 因子库详细说明
```

Agent 会自动顺藤摸瓜加载对应的 Context，免去了你所有的手动喂喂喂的麻烦。

## 常见问题解答

### Q1：我在配置文件里设置了模型，但好像没有生效？

**原因分析**：插件的模型配置依赖正确的文件位置和格式，以及已连接的 provider。

**检查步骤**：

1. **确认配置文件位置正确**：
   - 用户级配置（全局生效）：`~/.config/opencode/oh-my-openquant.jsonc`
   - 项目级配置（仅当前目录生效）：`.opencode/oh-my-openquant.jsonc`

2. **确认模型 ID 格式正确**：必须使用 `provider/model-id` 格式，例如：
   ```jsonc
   {
     "agents": {
       "sisyphus": {
         "model": "anthropic/claude-opus-4-6"
       }
     }
   }
   ```
   而不是单独的 `"claude-opus-4-6"`。

3. **确认 provider 已在 OpenCode 里连接**：如果你配置了 `openai/gpt-5.4` 但没有连接 OpenAI provider，模型解析会跳过你的配置，使用 fallback 链中的可用模型。

4. **对于 Sisyphus（主编排 Agent）**：Sisyphus 的 `mode` 是 `all`，在主 UI 中，如果你在 OpenCode 界面里手动选了模型，配置文件里的 `model` 字段**不会**覆盖 UI 选择。必须在 UI 里也切换到对应模型，或者通过 `ultrawork` 关键词触发 override。

5. **推荐做法：使用安装脚本自动生成配置**：

   ```bash
   bunx oh-my-openquant install
   ```

   安装脚本会根据你拥有的订阅（Claude/OpenAI/Gemini/Copilot 等）自动生成正确的配置文件，省去手动配置的麻烦。

6. **诊断工具**：

   ```bash
   bunx oh-my-openquant doctor
   ```

   该命令会检查所有 Agent 的模型解析状态，告诉你每个 Agent 实际使用的是哪个模型，以及为什么。

### Q2：Agent 数量只有三个，而且 OpenCode 原生的 Agent 也不可用了？

**关于 Agent 数量少的问题**：这是**预期行为**，不是 bug。

插件中每个 Agent 都有其模型要求 (Model Requirements)。如果相应的 provider 没有连接，Agent 就不会出现：

| Agent | 激活条件 |
| :---- | :------- |
| **Hephaestus** | 需要 OpenAI / GitHub Copilot / Venice / OpenCode 之一（必须连接）|
| **Oracle** | 需要 OpenAI、Google 或 Anthropic 之一 |
| **Librarian** | 需要 OpenCode Go、Anthropic 或 OpenCode |
| **Explore** | 需要 GitHub Copilot、OpenCode Go、Anthropic 或 OpenCode |
| **Metis** | 需要 Anthropic、OpenAI、OpenCode Go 或 Kimi |
| **Momus** | 需要 OpenAI、Anthropic 或 Google |
| **Sisyphus** | 需要至少一个可用模型（`requiresAnyModel`）|

如果你只连接了 Anthropic，那么 Hephaestus 不会出现（因为它严格需要 OpenAI 系 provider）。这不是错误，而是框架在保护你——它不会用错误的模型运行错误的 Agent。

**解决方案**：运行 `bunx oh-my-openquant install` 并如实回答你有哪些订阅，安装脚本会帮你配置好所有可用的 provider，让更多 Agent 自动激活。

**关于 OpenCode 原生 Agent 不可用的问题**：

OpenCode 的原生 Agent（`build`、`plan`）与插件 Agent 是共存关系，插件本身不会删除或屏蔽原生 Agent。如果你发现原生 Agent 消失了，可能的原因是：

- OpenCode 配置冲突（检查 `~/.config/opencode/opencode.json`）
- OpenCode 本身的版本兼容性问题

请运行 `bunx oh-my-openquant doctor` 检查健康状态，或在 [GitHub Issues](https://github.com/code-yeongyu/oh-my-openagent/issues) 反馈。

### Q3：`ulw` 命令是不是不用手动启动？

**是的，不需要手动启动。**

`ulw`（和 `ultrawork`）**不是一个独立的 CLI 命令，也不是一个需要启动的进程**。它只是一个你在聊天消息里输入的关键词。

**使用方法**：直接在消息框里打，例如：

```
ulw 帮我构建一个动量因子，并做全面的 IC 验证
```

或者：

```
ultrawork 优化我的 CTA 策略的仓位管理模块
```

**插件会自动**：
1. 检测到消息中的 `ulw` 或 `ultrawork` 关键词
2. 切换到对应 Agent 配置的 ultrawork 高性能模型（如果你在配置里设置了 `ultrawork.model`）
3. 激活完整的 Agent 团队并发模式

代码块（\`\`\` 或 \`）里的 `ulw` 不会被触发，只有正文中的关键词才生效。

## 如何卸载 (Uninstallation)

要移除 oh-my-openquant:

1. **从你的 OpenCode 配置文件中去掉插件**

   编辑 `~/.config/opencode/opencode.json` (或 `opencode.jsonc`) ，并把 `"oh-my-openquant"` 从 `plugin` 数组中删掉：

   ```bash
   # 如果你有 jq 的话
   jq '.plugin = [.plugin[] | select(. != "oh-my-openquant")]' \
       ~/.config/opencode/opencode.json > /tmp/oc.json && \
       mv /tmp/oc.json ~/.config/opencode/opencode.json
   ```

2. **清除配置文件 (可选)**

   ```bash
   # 移除全局用户配置
   rm -f ~/.config/opencode/oh-my-openquant.json ~/.config/opencode/oh-my-openquant.jsonc

   # 移除当前项目的配置
   rm -f .opencode/oh-my-openquant.json .opencode/oh-my-openquant.jsonc
   ```

3. **确认卸载成功**

   ```bash
   opencode --version
   # 这个时候就应该没有任何关于插件的输出信息了
   ```
